# ht2-rev

Reverse engineering of `king.exe` from **Hard Truck 2: King of the Road** (*Дальнобойщики 2*), version `v 8.0 30.01.03`.

`king.exe` is built from C++ only (`src/`); there is no assembly file left. C++ owns all the program's data. The two long x87 procedures (the helicopter step, the trailer hitch solver) are translated instruction by instruction (`tools/x87_to_c.py`) so their rounding is the original's, and `tools/x87_test` checks them against the original machine code. The statically linked MFC 4.2 is replaced by own code with the same layouts (`src/engine/mfc.cpp`), gzip 1.2.4 is C++ (`src/terrain/gzip.cpp`, `terrain_grid.cpp`; `tools/gzip_test` compares its output with an older build's), and the game runs on the modern static C runtime instead of its 1999 one (`src/engine/crt.cpp` keeps the few helpers whose results differ). The x87 helpers (`src/common/x87.cpp`) are C++ compiled with `/fp:fast`, which makes them the FPU instructions the original used. See `CONVERSION_LOG.md`.

The program started as a full disassembly, `king.masm`, which assembled back into a byte-identical `king.exe` and had a switch per source file to put the original assembly back. It is deleted; the tag `last-masm` is the last commit that has it (`nmake ASM=1` there builds the original program).

The game is not included: building needs your own original `king.exe` (for resources), running needs an installed game.

## Layout

| Path | What it is |
|---|---|
| `src/` | the C++ rewrite; folders follow the original libraries (`engine`, `ai`, `script`, `sound`, `truck`, `terrain`, `marine`), file names follow the original units in `units.csv` |
| `src/truck/copter_step.cpp`, `hitch_solver.cpp` | the helicopter step and the hitch solver, generated by `tools/x87_to_c.py` |
| `src/engine/data_image.cpp`, `data.cpp` | the program's data: `_RDATA` and `_DATA` as byte images with real pointers, `_BSS` |
| `src/engine/crt.cpp` | `WinMain` and the shims between the old runtime's callers and the modern one |
| `src/common/king.h` | shared declarations: `KING_ALIAS`, `KING_VAR`, the untyped `CallC`/`CallStd`/`CallThis`/`CallVirt` |
| `src/common/x87.h` | x87 floating point as VC6 generated it |
| `units.csv` | the object files the program was linked from |
| `symbols.csv` | library function names |
| `extractResources.py` | copies the resources of the original `king.exe` into `king.res` |
| `tools/` | `smoke_world.py` (world-loading smoke test), `x87_to_c.py` and `x87_test` (the hitch solver and helicopter step against the original machine code), `gzip_test` (gzip against an older build) |

## Building

Needs VS 2022 Build Tools with the v142 (14.29) x86 toolset (`cl`, `link`), Windows 10 SDK, the DirectX 7 SDK `lib` folder and Python with `pefile`. Paths are set in the `Makefile`.

```
nmake "GAME_EXE=C:\path\to\king.exe"   # first build (creates king.res)
nmake                                  # king.exe
nmake clean
```

## Running

Run `king.exe` with the game folder as working directory, e.g. through [D2GI](https://github.com/REDPOWAR/D2GI) in windowed mode:

```powershell
Start-Process C:\test\king.exe -WorkingDirectory 'C:\Program Files (x86)\King'
```

To reach the world click **ИГРА**, then **НОВАЯ ИГРА** (real mouse input only), or run `py tools\smoke_world.py` at the main menu.

## Next: no assembly

Run the drive test after every step.

1. **Static initializers.** `WinMain` (`crt.cpp`) still runs the old initializer table `$L_66c000`..`$L_66c488`. Replace it with a C++ list of the same init functions in the same order, then with C++ global objects where the order doesn't matter.
2. *(Done.)* Rest of MFC, the old runtime, gzip and the exception funclets are C++ or the modern runtime; `src/asm` and the `ml` rule are gone.
3. *(Done.)* The x87 helpers are C++ in `src/common/x87.cpp`, compiled with `/fp:fast` so that they are the FPU instructions themselves. No inline `__asm` is left.
4. **Typed data.** Replace the raw images piece by piece with real C++ definitions: globals as typed variables (a struct when code reaches neighbouring labels by offset), strings, float/double constants with the same bit patterns, lookup tables, vtables as arrays of C++ functions. Then `KING_VAR` and the fixed addresses go.

## Calls and names

Most calls are typed direct calls of the C++ function. About 2,300 still go through an original label (`FUN_xxxxxx`) bound with `KING_ALIAS` and the untyped `CallC`, `CallStd`, `CallThis` (`king.h`), where the caller's argument types don't yet match the callee's prototype; virtual calls use `CallVirt`. A thiscall method is an `extern "C" __fastcall` function with an unused second (EDX) parameter; callers pass 0. Data at original addresses is `KING_VAR(type, name, address)`.

C++ is built with `/Zl /GS- /GR- /EHs-c-` and `/arch:IA32`; the `Makefile` names all libraries (`LIBS`, and the modern static runtime in `CRTLIBS`). The old VC6 runtime's entry points (heap, stdio, exit, errno, threads, exception handling) point at the modern runtime or at the shims in `src/engine/crt.cpp`. Converted code must not look inside a `FILE` (use `FILE_EOF`, `CRT_STREAM` from `king.h`).
